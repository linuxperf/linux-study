# 1.5 内核 64 位入口与早期页表

> **本节源码**：[`arch/x86/kernel/head_64.S`](../../linux/arch/x86/kernel/head_64.S)、[`arch/x86/boot/startup/map_kernel.c`](../../linux/arch/x86/boot/startup/map_kernel.c)、[`arch/x86/boot/startup/gdt_idt.c`](../../linux/arch/x86/boot/startup/gdt_idt.c)、[`arch/x86/kernel/head64.c`](../../linux/arch/x86/kernel/head64.c)
> **关键函数**：`__startup_64()`、`startup_64_setup_gdt_idt()`、`x86_64_start_kernel()`、`copy_bootdata()`、`x86_64_start_reservations()`
> **前置知识**：1.4 解压与重定位、虚拟地址转换与页表的基本概念

## 概述

解压结束只保证内核指令位于可访问的内存中，尚未建立完整的内核地址空间。未压缩内核的 `startup_64` 必须根据实际物理位置修正早期页表，再从恒等映射切换到内核高地址执行。之后 C 入口才能清零运行期数据、保存启动输入并进入通用初始化。本节特别区分早期位置无关代码、普通内核 C 代码与其他 CPU 的复用入口。

## 核心数据结构

| 对象 | 作用 | 生命周期或约束 |
|---|---|---|
| `early_top_pgt` | 早期页表根，供启动切换使用 | 包含过渡所需映射，不是已经完成构建的全部内核映射 |
| `level3_kernel_pgt` / `level2_kernel_pgt` | 内核高地址映射的中间层页表 | 根据实际放置位置修正物理地址 |
| `early_dynamic_pgts` | 早期页表页池 | 支持过渡映射和早期按需建表，容量有限 |
| `phys_base` | 内核镜像物理地址换算的基准 | 不能用通用直接映射公式替代所有内核镜像地址换算 |
| `initial_code` | 汇编最后间接调用的 C 入口地址 | 启动 CPU 指向 `x86_64_start_kernel()`；AP 启动时改为 `start_secondary()` |
| `%r15` | 启动 CPU 在早期调用间保存参数块物理地址 | 在 AP 入口清零，不把 AP 当成重新传入完整启动参数的启动 CPU |

页表修正见 [`arch/x86/boot/startup/map_kernel.c:87-217`](../../linux/arch/x86/boot/startup/map_kernel.c#L87-L217)，入口选择见 [`arch/x86/kernel/head_64.S:412-420`](../../linux/arch/x86/kernel/head_64.S#L412-L420)、[`arch/x86/kernel/head_64.S:479`](../../linux/arch/x86/kernel/head_64.S#L479) 与 [`arch/x86/kernel/smpboot.c:842-854`](../../linux/arch/x86/kernel/smpboot.c#L842-L854)。

## 主流程分析

以下为汇编与 C 之间的控制流，不把同名的压缩镜像入口包含在内：

```text
startup_64〔未压缩内核〕                 arch/x86/kernel/head_64.S
├── __pi_startup_64_setup_gdt_idt()      arch/x86/boot/startup/gdt_idt.c
├── verify_cpu()
├── __pi___startup_64()                 arch/x86/boot/startup/map_kernel.c
├── 装入 early_top_pgt，跳到高地址 common_startup_64
└── 间接调用 initial_code
    └── x86_64_start_kernel()           arch/x86/kernel/head64.c
        ├── reset_early_page_tables()
        ├── clear_bss()
        ├── idt_setup_early_handler()   arch/x86/kernel/idt.c
        ├── copy_bootdata()
        ├── load_ucode_bsp()
        └── x86_64_start_reservations()
            └── start_kernel()         init/main.c
```

### 先让“地址不符合链接预期”的代码可以安全运行

进入时 `%rsi` 是 `boot_params` 的物理地址，入口保存到 `%r15`。栈通过 RIP 相对寻址取得，随后建立临时 GDT 与 IDT 并检查 CPU，见 [`arch/x86/kernel/head_64.S:38-98`](../../linux/arch/x86/kernel/head_64.S#L38-L98)。

当前实际执行地址还不是链接器预期的内核高地址，因此不能随意取全局变量的绝对地址。`__startup_64()` 所在代码使用位置无关代码（Position-Independent Code，PIC）编译，并通过 `rip_rel_ptr()` 访问当前映射中的对象，约束说明见 [`arch/x86/boot/startup/map_kernel.c:78-85`](../../linux/arch/x86/boot/startup/map_kernel.c#L78-L85)。

调用处的 `__pi_` 前缀由构建规则统一添加，并非源码漏写了函数定义。相关规则还移除 ftrace、LTO 等插桩，见 [`arch/x86/boot/startup/Makefile:3-19`](../../linux/arch/x86/boot/startup/Makefile#L3-L19)、[`arch/x86/boot/startup/Makefile:42-52`](../../linux/arch/x86/boot/startup/Makefile#L42-L52)。

### 修正页表并跨越到高地址

汇编计算当前地址与内核虚拟地址的偏移，交给 `__pi___startup_64()`。该函数检查地址范围与对齐，修正页表中的物理地址，建立切换所需的恒等映射，同时保留内核高地址映射，见 [`arch/x86/boot/startup/map_kernel.c:87-217`](../../linux/arch/x86/boot/startup/map_kernel.c#L87-L217)。

然后装入新的页表根，并跳到高地址的公共入口：

[`arch/x86/kernel/head_64.S:135-140`](../../linux/arch/x86/kernel/head_64.S#L135-L140)（v6.18.60）

```asm
	movq	%rax, %cr3

	/* Branch to the common startup code at its kernel virtual address */
	ANNOTATE_RETPOLINE_SAFE
	jmp	*.Lcommon_startup_64(%rip)
```

换页表时新旧执行点都必须可取指；高地址跳转完成后，才有条件撤掉早先的过渡映射。不能把“写 `CR3`”单独看成一个与当前指令地址无关的操作。

### 公共汇编建立每 CPU 基本状态

`common_startup_64` 统一控制寄存器、选择 CPU 编号、取得当前任务的栈，设置 GDT、GS 基址与早期 IDT，最后间接调用 `initial_code`，见 [`arch/x86/kernel/head_64.S:198-420`](../../linux/arch/x86/kernel/head_64.S#L198-L420)。启动 CPU 使用初始任务与 CPU 0 的相应数据；AP 的 `secondary_startup_64` 在前面走另一段准备代码后进入这片公共逻辑。

### C 入口保存启动资料

`x86_64_start_kernel()` 重置早期页表，按实际页表层数调整相关基址，清零 BSS 与 brk 区域，再逐步建立早期异常处理，见 [`arch/x86/kernel/head64.c:222-277`](../../linux/arch/x86/kernel/head64.c#L222-L277)。注意这是未压缩内核的 BSS；解压器已清过自己的 BSS，二者并不是同一个程序实例。

`copy_bootdata()` 把外部参数块复制到内核自己的 `boot_params`，清洗不可信或不兼容字段，并组合命令行地址高低位后保存命令行。原始启动数据后续不必永久保留，见 [`arch/x86/kernel/head64.c:185-220`](../../linux/arch/x86/kernel/head64.c#L185-L220)。

最后，入口执行启动 CPU 微码早期加载，保留内核高地址映射，进入 `x86_64_start_reservations()`，再到 `start_kernel()`。这里仍是架构到通用内核的过渡，不是驱动初始化终点。

## 关键细节 / 设计考量

### 早期异常处理只能依靠已存在的条件

`bringup_idt_table` 不直接复用完整运行期 IDT，因为后者涉及的代码可能被 tracing 或 KASAN 插桩，并要求尚未建立的 CPU 状态。原因在 [`arch/x86/boot/startup/gdt_idt.c:12-24`](../../linux/arch/x86/boot/startup/gdt_idt.c#L12-L24) 中有明确说明。

### 页表初始化不是一次调用全部完成

本节解决进入内核虚拟地址与必要数据访问；`setup_arch()` 中的 `init_mem_mapping()` 才扩展直接映射。早期页故障也有受限的动态建表逻辑，见 [`arch/x86/kernel/head64.c:71-175`](../../linux/arch/x86/kernel/head64.c#L71-L175)。这不等于已经具备普通进程缺页处理能力。

## 可观测性

- **最早指令应使用虚拟机调试器观察**：观察 `CR3`、`CR4.LA57`、当前 `%rip` 和 `%rsi` / `%r15`，比假定早期 C 函数可被 ftrace 插桩更可靠。页表切换点见本节汇编链接；带 `__pi_` 的启动代码明确移除了 ftrace 编译钩子。
- **登录后只能检查部分交接结果**：`/sys/kernel/boot_params/data` 可验证保存的数据，不提供页表切换时序，导出见 [`arch/x86/kernel/ksysfs.c:30-45`](../../linux/arch/x86/kernel/ksysfs.c#L30-L45)，依赖当前 `CONFIG_SYSFS=y`。
- **内核阶段的早期日志另用早期控制台**：`earlyprintk` 在 [`arch/x86/kernel/early_printk.c:449`](../../linux/arch/x86/kernel/early_printk.c#L449) 注册为早期参数，当前 `CONFIG_EARLY_PRINTK=y`。但参数解析发生得更晚，不能保证覆盖 `startup_64` 的最初指令。
- **不要登录后才对本节 `__init` 函数安装探针**：初始化结束会回收相应内存，回收顺序见 [`init/main.c:1445-1454`](../../linux/init/main.c#L1445-L1454)。符号曾在镜像中存在，不代表其地址始终有可执行代码。

## 小结

- 本节的 `startup_64` 位于未压缩内核，和解压器入口不是同一符号。
- 位置无关启动代码根据实际物理放置修正早期页表，再跳到内核高地址。
- 临时页表、早期 IDT、栈和 GS 基址共同建立进入普通 C 代码的条件。
- 启动参数与命令行复制完成后，内核不再依赖引导方原始缓冲区长期存活。
- AP 复用部分汇编，但不重新执行启动 CPU 的全部 C 初始化。

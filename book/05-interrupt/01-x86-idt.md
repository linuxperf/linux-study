# 5.1 x86_64 中断与异常体系：向量、IDT 与中断栈

> **前置知识**：4.6 内核虚拟地址空间与 vmalloc（cpu_entry_area）、7.1 并发来源与执行上下文

## 概述

CPU 在执行指令流的过程中，随时可能被两类事件打断：一类来自 CPU 外部，例如网卡收到数据包、定时器到期，称为**中断**（Interrupt）；另一类由当前执行的指令本身引起，例如除零、访问未映射的页、执行 `int3`，称为**异常**（Exception）。无论哪一类，x86 都用一个 0～255 的**向量号**（Vector）标识它，再以向量号为下标查**中断描述符表**（Interrupt Descriptor Table，IDT），找到处理程序的入口地址。

Linux 在 x86_64 上为这 256 个向量建立了一张固定的布局：0～31 留给 CPU 定义的异常，32 以上分配给外部设备，最高的一段留给 IPI、本地 APIC 定时器等"系统向量"。内核在启动过程中分几步填写 IDT，最终把它映射到 cpu_entry_area 的只读页上。

本节先介绍向量的分类与布局，再分析门描述符、任务状态段（TSS）中的中断栈表（Interrupt Stack Table，IST）以及 IDT 的初始化过程。CPU 跳到入口之后发生的事情——保存寄存器、切换栈、调用 C 处理函数——留给 5.2 节。

## 中断与异常的分类

Intel SDM 按"报告方式"和"能否恢复"把异常分为三类：

| 类别 | 英文 | 保存的返回地址 | 典型例子 |
|---|---|---|---|
| 故障 | Fault | 引起异常的那条指令 | #PF、#GP、#UD；处理后重新执行该指令 |
| 陷阱 | Trap | 引起异常的下一条指令 | #BP（`int3`）、#OF（`into`）、#DB 的单步 |
| 终止 | Abort | 不保证精确 | #DF、#MC；通常无法恢复 |

*表 5-1：x86 异常的三种类型*

中断则按来源分为：

- **可屏蔽外部中断**：经由本地 APIC（Local APIC，5.5 节）投递，`RFLAGS.IF = 0` 时被推迟。设备中断、本地 APIC 定时器、处理器间中断（Inter-Processor Interrupt，IPI）都属于此类。
- **不可屏蔽中断**（Non-Maskable Interrupt，NMI）：向量固定为 2，不受 `IF` 控制，常用于硬件错误报告、性能计数器溢出和看门狗（5.4 节）。
- **软件中断**：`int n` 指令。x86_64 Linux 只保留了 `int $0x80`（32 位兼容系统调用）和 `int3`。

其中 #DF、#TS、#NP、#SS、#GP、#PF、#AC、#CP、#VC 这几个向量会由 CPU 额外压入一个**错误码**（Error Code），例如 #PF 的错误码说明是读还是写、来自用户态还是内核态（4.8 节）。`X86_TRAP_IRET`（32）并不是硬件向量，只是 32 位内核用来标识 IRET 失败的软件编号。

同一文件开头定义的 `EVENT_TYPE_*`（`arch/x86/include/asm/trapnr.h:8-15`）是 FRED、VT-x 与 SVM 共用的事件类型编码，FRED 用它区分外部中断、NMI、硬件异常和软件异常（5.2 节）。

### Linux 的向量布局

```c
// arch/x86/include/asm/irq_vectors.h:6-38（v6.18.60）
/*
 * Linux IRQ vector layout.
 *
 * There are 256 IDT entries (per CPU - each entry is 8 bytes) which can
 * be defined by Linux. They are used as a jump table by the CPU when a
 * given vector is triggered - by a CPU-external, CPU-internal or
 * software-triggered event.
 *
 * Linux sets the kernel code address each entry jumps to early during
 * bootup, and never changes them. This is the general layout of the
 * IDT entries:
 *
 *  Vectors   0 ...  31 : system traps and exceptions - hardcoded events
 *  Vectors  32 ... 127 : device interrupts
 *  Vector  128         : legacy int80 syscall interface
 *  Vectors 129 ... FIRST_SYSTEM_VECTOR-1 : device interrupts
 *  Vectors FIRST_SYSTEM_VECTOR ... 255   : special interrupts
 *
 * 64-bit x86 has per CPU IDT tables, 32-bit has one shared IDT table.
 *
 * This file enumerates the exact layout of them:
 */

/* This is used as an interrupt vector when programming the APIC. */
#define NMI_VECTOR			0x02

/*
 * IDT vectors usable for external interrupt sources start at 0x20.
 * (0x80 is the syscall vector, 0x30-0x3f are for ISA)
 */
#define FIRST_EXTERNAL_VECTOR		0x20

#define IA32_SYSCALL_VECTOR		0x80
```

注释第 24 行说"64-bit x86 has per CPU IDT tables"，但从下文 `idt.c` 可以看到，当前实现中所有 CPU 实际上共享同一张 `idt_table`。真正 per-CPU 的是**向量到中断描述符的映射表** `vector_irq`（5.8 节）：同一个向量号在不同 CPU 上可以对应不同的设备中断，这是 x86_64 能支持远多于 256 个设备中断的关键。

最高的一段是系统向量，每一个都有专门的入口函数：


另外，向量号的高 4 位即本地 APIC 的**中断优先级类**：APIC 只有在新中断的优先级类高于当前正在服务的中断时才会打断它。把定时器和 IPI 放在最高的 `0xe`/`0xf` 类，保证它们不会被设备中断挡住。

## 核心数据结构

### 门描述符

IDT 的每一项是一个 16 字节的**门描述符**（Gate Descriptor），内核用 `struct gate_struct` 描述：

```c
// arch/x86/include/asm/desc_defs.h:119-145（v6.18.60）
struct idt_bits {
	u16		ist	: 3,	// [注] IST 下标，0 表示不切换到 IST 栈
			zero	: 5,
			type	: 5,	// [注] 门类型：中断门 0xE / 陷阱门 0xF
			dpl	: 2,	// [注] 允许 int n 访问该门的最低特权级
			p	: 1;	// [注] 存在位
} __attribute__((packed));

struct idt_data {
	unsigned int	vector;
	unsigned int	segment;
	struct idt_bits	bits;
	const void	*addr;
};

struct gate_struct {
	u16		offset_low;	// [注] 入口地址 bit 0-15
	u16		segment;	// [注] 代码段选择子，总是 __KERNEL_CS
	struct idt_bits	bits;
	u16		offset_middle;	// [注] 入口地址 bit 16-31
#ifdef CONFIG_X86_64
	u32		offset_high;	// [注] 入口地址 bit 32-63
	u32		reserved;
#endif
} __attribute__((packed));

typedef struct gate_struct gate_desc;
```

`struct idt_data` 是内核自己用的"未打包"形式，`idt_init_desc()`（`arch/x86/include/asm/desc.h:418-430`）负责把它拆成硬件格式。门类型的取值：

```c
// arch/x86/include/asm/desc_defs.h:90-95（v6.18.60）
enum {
	GATE_INTERRUPT = 0xE,
	GATE_TRAP = 0xF,
	GATE_CALL = 0xC,
	GATE_TASK = 0x5,
};
```

中断门与陷阱门的唯一区别在于：经由**中断门**进入时 CPU 会自动清除 `RFLAGS.IF`，经由陷阱门则不会。`idt.c` 中定义的辅助宏全部使用中断门：

```c
// arch/x86/kernel/idt.c:16-53（v6.18.60）
#define DPL0		0x0
#define DPL3		0x3

#define DEFAULT_STACK	0

#define G(_vector, _addr, _ist, _type, _dpl, _segment)	\
	{						\
		.vector		= _vector,		\
		.bits.ist	= _ist,			\
		.bits.type	= _type,		\
		.bits.dpl	= _dpl,			\
		.bits.p		= 1,			\
		.addr		= _addr,		\
		.segment	= _segment,		\
	}

/* Interrupt gate */
#define INTG(_vector, _addr)				\
	G(_vector, _addr, DEFAULT_STACK, GATE_INTERRUPT, DPL0, __KERNEL_CS)

/* System interrupt gate */
#define SYSG(_vector, _addr)				\
	G(_vector, _addr, DEFAULT_STACK, GATE_INTERRUPT, DPL3, __KERNEL_CS)

#ifdef CONFIG_X86_64
/*
 * Interrupt gate with interrupt stack. The _ist index is the index in
 * the tss.ist[] array, but for the descriptor it needs to start at 1.
 */
#define ISTG(_vector, _addr, _ist)			\
	G(_vector, _addr, _ist + 1, GATE_INTERRUPT, DPL0, __KERNEL_CS)
#else
#define ISTG(_vector, _addr, _ist)	INTG(_vector, _addr)
#endif

/* Task gate */
#define TSKG(_vector, _gdt)				\
	G(_vector, NULL, DEFAULT_STACK, GATE_TASK, DPL0, _gdt << 3)
```

- `INTG`：普通中断门，DPL 为 0，用户态无法用 `int n` 直接触发。
- `SYSG`：DPL 为 3 的"系统门"，允许用户态执行 `int3`、`into`、`int $0x80`。
- `ISTG`：在门描述符中填写 IST 下标，CPU 进入时无条件切换到 TSS 中指定的栈。
- `TSKG`：任务门，仅 32 位内核用于 #DF。

**全部使用中断门**是 Linux 的一个基本设计：所有异常和中断的入口代码都在关中断状态下开始执行，由 C 代码视需要再打开中断（例如 #PF 处理在确认来自用户态或原先开中断时调用 `local_irq_enable()`）。这样入口汇编无需担心在保存寄存器、切换 GS 和 CR3 的过程中被中断打断。

### TSS 与中断栈表

x86_64 的**任务状态段**（Task State Segment，TSS）已不再用于硬件任务切换，只剩下两个用途：为特权级切换提供内核栈指针（`sp0`），以及为 IST 提供最多 7 个备用栈：

```c
// arch/x86/include/asm/processor.h:308-327（v6.18.60）
struct x86_hw_tss {
	u32			reserved1;
	u64			sp0;	// [注] 从用户态进入时 CPU 加载的 RSP
	u64			sp1;

	/*
	 * Since Linux does not use ring 2, the 'sp2' slot is unused by
	 * hardware.  entry_SYSCALL_64 uses it as scratch space to stash
	 * the user RSP value.
	 */
	u64			sp2;

	u64			reserved2;
	u64			ist[7];	// [注] 中断栈表（Interrupt Stack Table）
	u32			reserved3;
	u32			reserved4;
	u16			reserved5;
	u16			io_bitmap_base;

} __attribute__((packed));
```

CPU 投递中断或异常时选择栈的规则是：

1. 如果门描述符的 `ist` 字段非 0，无论当前特权级如何，都把 RSP 设为 `tss.ist[ist-1]`；
2. 否则如果发生了特权级切换（用户态 → 内核态），把 RSP 设为 `tss.sp0`；
3. 否则（内核态被打断）继续使用当前栈。

x86_64 Linux 中 `sp0` 不指向当前任务的内核栈，而是固定指向 cpu_entry_area 中的**入口栈**（entry stack，也称 trampoline stack）：

```c
// arch/x86/kernel/cpu/common.c:2465-2469（v6.18.60）
	/*
	 * sp0 points to the entry trampoline stack regardless of what task
	 * is running.
	 */
	load_sp0((unsigned long)(cpu_entry_stack(cpu) + 1));
```

原因与页表隔离（Page Table Isolation，PTI，`CONFIG_MITIGATION_PAGE_TABLE_ISOLATION=y`）有关：从用户态进入时 CR3 还是用户页表，只有 cpu_entry_area 被映射到用户页表中，CPU 压栈的目标必须位于那里。入口代码切换到内核 CR3 之后，再由 `sync_regs()` 把硬件帧复制到任务的内核栈上（5.2 节）。因此上下文切换时也无需更新 `sp0`（`arch/x86/include/asm/switch_to.h:69-79` 的 `update_task_stack()` 只为 Xen PV 更新它）。

Linux 使用了 7 个 IST 槽位中的 5 个：

```c
// arch/x86/include/asm/page_64_types.h:18-31（v6.18.60）
#define EXCEPTION_STACK_ORDER (1 + KASAN_STACK_ORDER)
#define EXCEPTION_STKSZ (PAGE_SIZE << EXCEPTION_STACK_ORDER)

#define IRQ_STACK_ORDER (2 + KASAN_STACK_ORDER)
#define IRQ_STACK_SIZE (PAGE_SIZE << IRQ_STACK_ORDER)

/*
 * The index for the tss.ist[] array. The hardware limit is 7 entries.
 */
#define	IST_INDEX_DF		0
#define	IST_INDEX_NMI		1
#define	IST_INDEX_DB		2
#define	IST_INDEX_MCE		3
#define	IST_INDEX_VC		4
```

本书配置未开启 KASAN，`KASAN_STACK_ORDER` 为 0：每个异常栈 8 KB，硬中断栈 16 KB，任务内核栈（`THREAD_SIZE`）也是 16 KB。

这些异常栈位于 cpu_entry_area 中，每个栈之间夹一页不映射的保护页（Guard Page），栈溢出会立即触发 #DF 而不是悄悄踩坏相邻数据：

```c
// arch/x86/include/asm/cpu_entry_area.h:19-56（v6.18.60）

	char	DB_stack_guard[guardsize];			\
	char	DB_stack[EXCEPTION_STKSZ];			\
	char	MCE_stack_guard[guardsize];			\
	char	MCE_stack[EXCEPTION_STKSZ];			\
	char	VC_stack_guard[guardsize];			\
	char	VC_stack[optional_stack_size];			\
	char	VC2_stack_guard[guardsize];			\
	char	VC2_stack[optional_stack_size];			\
	char	IST_top_guard[guardsize];			\

/* The exception stacks' physical storage. No guard pages required */
struct exception_stacks {
	ESTACKS_MEMBERS(0, VC_EXCEPTION_STKSZ)
};

/* The effective cpu entry area mapping with guard pages. */
struct cea_exception_stacks {
	ESTACKS_MEMBERS(PAGE_SIZE, EXCEPTION_STKSZ)
};

/*
 * The exception stack ordering in [cea_]exception_stacks
 */
enum exception_stack_ordering {
	ESTACK_DF,
	ESTACK_NMI,
	ESTACK_DB,
	ESTACK_MCE,
	ESTACK_VC,
	ESTACK_VC2,
	N_EXCEPTION_STACKS

```

同一个宏展开两次：`struct exception_stacks` 是 per-CPU 区域中的物理存储，不含保护页；`struct cea_exception_stacks` 是 cpu_entry_area 中的虚拟映射布局，每个栈前留一页空洞。`#VC` 栈只在 AMD SEV-ES 客户机中才真正映射（`CONFIG_AMD_MEM_ENCRYPT=y`）。

`tss_setup_ist()` 把各栈的栈顶地址写入 TSS：

```c
// arch/x86/kernel/cpu/common.c:2338-2348（v6.18.60）
#ifdef CONFIG_X86_64
static inline void tss_setup_ist(struct tss_struct *tss)
{
	/* Set up the per-CPU TSS IST stacks */
	tss->x86_tss.ist[IST_INDEX_DF] = __this_cpu_ist_top_va(DF);
	tss->x86_tss.ist[IST_INDEX_NMI] = __this_cpu_ist_top_va(NMI);
	tss->x86_tss.ist[IST_INDEX_DB] = __this_cpu_ist_top_va(DB);
	tss->x86_tss.ist[IST_INDEX_MCE] = __this_cpu_ist_top_va(MCE);
	/* Only mapped when SEV-ES is active */
	tss->x86_tss.ist[IST_INDEX_VC] = __this_cpu_ist_top_va(VC);
}
```

### 为什么需要 IST

IST 解决的是"当前栈不可信"的问题，典型场景有三个：

- **#DF**：双重故障往往由内核栈溢出引起（压栈时访问了保护页，引发 #PF，再压栈时又失败）。此时当前栈已经不可用，必须换到一个确定可用的栈。
- **NMI 与 #MC**：它们可以在任何时刻发生，包括 `syscall` 指令刚执行、RSP 仍是用户栈指针、尚未切换到内核栈的那几条指令之间。`syscall` 不会自动切换栈，如果 NMI 沿用当前 RSP，就会把数据写到用户控制的地址上。
- **#DB**：硬件断点同样可能命中 `syscall` 入口的这段窗口。

IST 的代价是**不可重入**：同一向量第二次进入时，CPU 仍会把 RSP 设到同一个栈顶，覆盖第一次留下的帧。NMI 的嵌套处理（5.4 节）和 `#VC` 入口中的 `vc_switch_off_ist()` 都是为了规避这个问题。正因如此，Linux 只给确实需要的少数向量配置 IST。

### 硬中断栈

设备中断和系统向量不使用 IST，而是在进入 C 代码后由软件切换到 per-CPU 的**硬中断栈**（hardirq stack，5.2 节）。它的物理存储是 per-CPU 变量，开启 `CONFIG_VMAP_STACK` 时再用 `vmap()` 映射一份带保护页的别名：

```c
// arch/x86/kernel/irq_64.c:29-56（v6.18.60）
DEFINE_PER_CPU_CACHE_HOT(bool, hardirq_stack_inuse);
DEFINE_PER_CPU_PAGE_ALIGNED(struct irq_stack, irq_stack_backing_store) __visible;

#ifdef CONFIG_VMAP_STACK
/*
 * VMAP the backing store with guard pages
 */
static int map_irq_stack(unsigned int cpu)
{
	char *stack = (char *)per_cpu_ptr(&irq_stack_backing_store, cpu);
	struct page *pages[IRQ_STACK_SIZE / PAGE_SIZE];
	void *va;
	int i;

	for (i = 0; i < IRQ_STACK_SIZE / PAGE_SIZE; i++) {
		phys_addr_t pa = per_cpu_ptr_to_phys(stack + (i << PAGE_SHIFT));

		pages[i] = pfn_to_page(pa >> PAGE_SHIFT);
	}

	va = vmap(pages, IRQ_STACK_SIZE / PAGE_SIZE, VM_MAP, PAGE_KERNEL);
	if (!va)
		return -ENOMEM;

	/* Store actual TOS to avoid adjustment in the hotpath */
	per_cpu(hardirq_stack_ptr, cpu) = va + IRQ_STACK_SIZE - 8;
	return 0;
}
```

`hardirq_stack_ptr` 指向栈顶下方 8 字节处：切换栈时会把原 RSP 存在这个位置，以便回溯器（unwinder）能从中断栈链回被打断的栈。`hardirq_stack_inuse` 标记当前是否已在中断栈上，避免嵌套时重复切换。

汇总起来，一个 x86_64 CPU 上同时存在以下几类栈：

| 栈 | 大小 | 位置 | 使用者 |
|---|---|---|---|
| 任务内核栈 | 16 KB | vmalloc 区（`CONFIG_VMAP_STACK`） | 系统调用、来自用户态的异常 |
| 入口栈 | 1 页以内 | cpu_entry_area | 从用户态进入的头几条指令 |
| 硬中断栈 | 16 KB | vmap 别名 | 设备中断、系统向量、软中断 |
| IST 栈 | 各 8 KB | cpu_entry_area | #DF、NMI、#DB、#MC、#VC |

## 主流程分析：IDT 的建立

### 初始化调用链

IDT 不是一次填完的。早期内核还没有页表、per-CPU 区和 TSS，许多处理函数无法工作，因此 IDT 随启动进程分阶段完善：

```
x86_64_start_kernel()                          arch/x86/kernel/head64.c
└── idt_setup_early_handler()                  arch/x86/kernel/idt.c    ① 32 个异常 → early_idt_handler_array
start_kernel()                                 init/main.c
├── setup_arch()                               arch/x86/kernel/setup.c
│   ├── idt_setup_early_traps()                                         ② #DB、#BP（及 TDX 的 #VE）
│   ├── init_mem_mapping()
│   └── cpu_init_replace_early_idt()           arch/x86/kernel/cpu/common.c
│       └── idt_setup_early_pf()                                        ③ 真正的 #PF 处理函数
├── trap_init()                                arch/x86/kernel/traps.c
│   ├── setup_cpu_entry_areas()                                         建立 cpu_entry_area
│   ├── cpu_init_exception_handling(true)      arch/x86/kernel/cpu/common.c  填写 TSS.ist[]、加载 TR
│   ├── idt_setup_traps()                                               ④ 全部异常门（含 IST）
│   └── cpu_init()
└── init_IRQ()                                 arch/x86/kernel/irqinit.c
    └── native_init_IRQ()
        └── idt_setup_apic_and_irq_gates()                              ⑤ 系统向量 + 设备中断桩，IDT 只读
```

**第 ① 步**发生在内核刚进入 64 位 C 代码时（`arch/x86/kernel/head64.c:276`）。`early_idt_handler_array`（`arch/x86/kernel/head_64.S:488-505`）为每个异常生成一个小桩，统一跳到 `do_early_exception()`。这个阶段最主要的任务是处理早期页表的 #PF——内核通过缺页按需建立直接映射，同时允许 `rdmsr_safe()` 之类的异常修复。

**第 ②、③ 步**在 `setup_arch()` 中。`idt_setup_early_traps()` 尽早装上 #DB 和 #BP，使内核调试器可以在启动早期工作；#PF 必须等 `init_mem_mapping()` 建好完整的直接映射之后才能换成真正的 `exc_page_fault()`（`arch/x86/kernel/idt.c:249-260` 的注释说明了原因）：

```c
// arch/x86/kernel/idt.c:59-76（v6.18.60）
/*
 * Early traps running on the DEFAULT_STACK because the other interrupt
 * stacks work only after cpu_init().
 */
static const __initconst struct idt_data early_idts[] = {
	INTG(X86_TRAP_DB,		asm_exc_debug),
	SYSG(X86_TRAP_BP,		asm_exc_int3),

#ifdef CONFIG_X86_32
	/*
	 * Not possible on 64-bit. See idt_setup_early_pf() for details.
	 */
	INTG(X86_TRAP_PF,		asm_exc_page_fault),
#endif
#ifdef CONFIG_INTEL_TDX_GUEST
	INTG(X86_TRAP_VE,		asm_exc_virtualization_exception),
#endif
};
```

注意此时 #DB 用的是 `INTG` 而不是 `ISTG`：TSS 还没设置，IST 栈不可用。

### trap_init：异常门与 IST

`trap_init()` 在 `start_kernel()` 中调用（`init/main.c:930`），此时内存分配器已经可用：

```c
// arch/x86/kernel/traps.c:1561-1577（v6.18.60）
void __init trap_init(void)
{
	/* Init cpu_entry_area before IST entries are set up */
	setup_cpu_entry_areas();

	/* Init GHCB memory pages when running as an SEV-ES guest */
	sev_es_init_vc_handling();

	/* Initialize TSS before setting up traps so ISTs work */
	cpu_init_exception_handling(true);

	/* Setup traps as cpu_init() might #GP */
	if (!cpu_feature_enabled(X86_FEATURE_FRED))
		idt_setup_traps();

	cpu_init();
}
```

顺序很重要：先建立 cpu_entry_area（IST 栈的映射在其中），再填写 TSS 并加载任务寄存器，最后才安装引用 IST 的门描述符。`cpu_init_exception_handling()` 也会被每个 AP（Application Processor）在启动时调用（`arch/x86/kernel/smpboot.c:251`）：

```c
// arch/x86/kernel/cpu/common.c:2373-2413（v6.18.60）
void cpu_init_exception_handling(bool boot_cpu)
{
	struct tss_struct *tss = this_cpu_ptr(&cpu_tss_rw);
	int cpu = raw_smp_processor_id();

	/* paranoid_entry() gets the CPU number from the GDT */
	setup_getcpu(cpu);

	/* For IDT mode, IST vectors need to be set in TSS. */
	if (!cpu_feature_enabled(X86_FEATURE_FRED))
		tss_setup_ist(tss);
	tss_setup_io_bitmap(tss);
	set_tss_desc(cpu, &get_cpu_entry_area(cpu)->tss.x86_tss);

	load_TR_desc();

	/* GHCB needs to be setup to handle #VC. */
	setup_ghcb();
	...
	if (cpu_feature_enabled(X86_FEATURE_FRED)) {
		/* The boot CPU has enabled FRED during early boot */
		if (!boot_cpu)
			cpu_init_fred_exceptions();

		cpu_init_fred_rsps();
	} else {
		load_current_idt();
	}
}
```

`setup_getcpu()` 把 CPU 编号写进 GDT 的一个段描述符，这样在 GS 尚未确定的 paranoid 入口中，也能用 `rdpid`/`lsl` 读出当前 CPU 编号，进而找到该 CPU 的 GSBASE（5.2 节）。

`idt_setup_traps()` 安装的默认异常表如下：

表中的 `asm_exc_*` 符号由 `idtentry.h` 中的 `DECLARE_IDTENTRY*()` 宏在汇编里生成（5.2 节）。#PF 不在此表中，它已在第 ③ 步安装；#BP 也已在第 ② 步作为 `SYSG` 安装。`idt_setup_from_table()` 在写入每个门的同时把向量号记入 `system_vectors` 位图，后续步骤据此跳过已占用的向量：

```c
// arch/x86/kernel/idt.c:193-204（v6.18.60）
static __init void
idt_setup_from_table(gate_desc *idt, const struct idt_data *t, int size, bool sys)
{
	gate_desc desc;

	for (; size > 0; t++, size--) {
		idt_init_desc(&desc, t);
		write_idt_entry(idt, t->vector, &desc);
		if (sys)
			set_bit(t->vector, system_vectors);
	}
}
```

### idt_setup_apic_and_irq_gates：设备中断与系统向量

`init_IRQ()`（`init/main.c:976`）经 `x86_init.irqs.intr_init` 调用 `native_init_IRQ()`，后者完成 IDT 的最后一步：

```c
// arch/x86/kernel/idt.c:284-315（v6.18.60）
void __init idt_setup_apic_and_irq_gates(void)
{
	int i = FIRST_EXTERNAL_VECTOR;
	void *entry;

	idt_setup_from_table(idt_table, apic_idts, ARRAY_SIZE(apic_idts), true);

	for_each_clear_bit_from(i, system_vectors, FIRST_SYSTEM_VECTOR) {
		entry = irq_entries_start + IDT_ALIGN * (i - FIRST_EXTERNAL_VECTOR);
		set_intr_gate(i, entry);
	}

#ifdef CONFIG_X86_LOCAL_APIC
	for_each_clear_bit_from(i, system_vectors, NR_VECTORS) {
		/*
		 * Don't set the non assigned system vectors in the
		 * system_vectors bitmap. Otherwise they show up in
		 * /proc/interrupts.
		 */
		entry = spurious_entries_start + IDT_ALIGN * (i - FIRST_SYSTEM_VECTOR);
		set_intr_gate(i, entry);
	}
#endif
	/* Map IDT into CPU entry area and reload it. */
	idt_map_in_cea();
	load_idt(&idt_descr);

	/* Make the IDT table read only */
	set_memory_ro((unsigned long)&idt_table, 1);

	idt_setup_done = true;
}
```

它做了四件事：

1. 用 `apic_idts`（`arch/x86/kernel/idt.c:133-170`）安装系统向量：重调度 IPI、函数调用 IPI、本地定时器、irq_work、APIC 错误与伪中断等，每个都直接指向独立的 `asm_sysvec_*` 入口。
2. 把 `0x20`～`0xea` 中尚未占用的向量全部指向 `irq_entries_start` 数组中对应的小桩。
3. 把剩余未分配的系统向量指向 `spurious_entries_start`，收到时按伪中断处理。
4. 把 IDT 重新映射到 cpu_entry_area 的固定只读地址，并把原 `idt_table` 也设为只读。

第 4 步的注释（`arch/x86/kernel/idt.c:270-275`）说明了动机：`sidt` 指令在用户态也可执行，如果它返回的是内核映像中的地址，就会泄露 KASLR 的随机偏移；固定地址的只读别名既不泄露信息，也防止任意写漏洞篡改 IDT。

### 设备中断入口桩

设备中断共用一个 C 处理函数 `common_interrupt()`，但 CPU 不会告诉处理程序"这是第几号向量"。Linux 的解决办法是为每个外部向量生成一个 8 字节的小桩，把向量号压栈后跳到公共入口：

```asm
// arch/x86/include/asm/idtentry.h:545-558（v6.18.60）
	.align IDT_ALIGN
SYM_CODE_START(irq_entries_start)
    vector=FIRST_EXTERNAL_VECTOR
    .rept NR_EXTERNAL_VECTORS
	UNWIND_HINT_IRET_REGS
0 :
	ENDBR
	.byte	0x6a, vector
	jmp	asm_common_interrupt
	/* Ensure that the above is IDT_ALIGN bytes max */
	.fill 0b + IDT_ALIGN - ., 1, 0xcc
	vector = vector+1
    .endr
SYM_CODE_END(irq_entries_start)
```

`0x6a imm8` 是 `push imm8` 的编码，2 字节；`jmp rel8/rel32` 最多 5 字节，合起来不超过 `IDT_ALIGN`。本书配置未开启 `CONFIG_X86_KERNEL_IBT`，`ENDBR` 为空，`IDT_ALIGN` 为 8（`arch/x86/include/asm/idtentry.h:8`）。`push imm8` 会把立即数**符号扩展**为 64 位，向量 `0x80` 以上会变成负数，因此 C 入口中用 `(u32)(u8)error_code` 截回 8 位（5.2 节）。压入的位置恰好是异常错误码所在的槽位，于是设备中断可以复用"带错误码异常"的入口宏。

## 关键细节 / 设计考量

### 共享 IDT 与 per-CPU 向量表

早期 x86_64 内核曾计划给每个 CPU 一张 IDT，但最终采用的方案是：IDT 全局共享，所有设备向量都指向同一组桩，再由 per-CPU 数组 `vector_irq[]`（`arch/x86/kernel/irqinit.c:50-52`）把"本 CPU 上的向量号"翻译为 `struct irq_desc`。这样既不需要为每个 CPU 维护一份 4 KB 的 IDT，又能让同一个向量号在不同 CPU 上服务不同设备。整机可用的设备中断数约为 203 × CPU 数，`NR_IRQS` 的计算（`arch/x86/include/asm/irq_vectors.h:130-137`）也基于每 CPU 64 个的估计。

### FRED：IDT 的替代者

灵活返回与事件投递（Flexible Return and Event Delivery，FRED）是 Intel 为取代 IDT 事件投递机制设计的新架构，v6.9 起由 `CONFIG_X86_FRED` 支持。FRED 下 CPU 不再查 IDT，而是跳到 `IA32_FRED_CONFIG` 指定的两个固定入口（用户态 / 内核态各一个），在扩展的栈帧中直接给出事件类型与向量号，由软件分发；栈切换改用"栈级别"（stack level）而不是 IST，天然支持嵌套；返回则用 `ERETU`/`ERETS` 取代 `IRET`，并自动处理 GS 与 NMI 屏蔽。

本书配置开启了 `CONFIG_X86_FRED`，但它默认不启用：

```c
// arch/x86/kernel/cpu/common.c:1731-1734（v6.18.60）
	/* Minimize the gap between FRED is available and available but disabled. */
	arglen = cmdline_find_option(boot_command_line, "fred", arg, sizeof(arg));
	if (arglen != 2 || strncmp(arg, "on", 2))
		setup_clear_cpu_cap(X86_FEATURE_FRED);
```

只有在支持 FRED 的 CPU 上并传入 `fred=on`，内核才会走 FRED 路径。本章其余部分以默认的 IDT 路径为准，5.2 节会简要对比 FRED 的分发方式。

### int3 与 int80 的 DPL

`SYSG` 门的 DPL 为 3。`int3` 必须能被用户态调用（调试器在用户程序中插入断点）；`into` 同理；`int $0x80` 则是 32 位程序的系统调用入口（仅 `CONFIG_IA32_EMULATION` 且 `ia32_enabled()` 时安装，`arch/x86/kernel/idt.c:122-128`）。其余所有门的 DPL 为 0，用户态执行 `int $0x0e` 之类的指令不会伪造出一次缺页，而是因权限不足触发 #GP。

## 动手实验

### 查看系统向量统计

`/proc/interrupts` 的末尾几行是系统向量的 per-CPU 计数，由 `arch_show_interrupts()`（`arch/x86/kernel/irq.c:68`）输出：

```bash
# 在 dev 虚拟机中执行
grep -E '^ *(NMI|LOC|SPU|RES|CAL|TLB|IWI|ERR|MIS):' /proc/interrupts
```

`LOC` 对应 `LOCAL_TIMER_VECTOR`，`RES` 对应重调度 IPI，`CAL` 对应函数调用 IPI，`TLB` 是借用 `CALL_FUNCTION` 向量完成的 TLB 刷新，`IWI` 对应 irq_work。

### 观察 IDT 地址

```bash
# sidt 在用户态可执行；需要 UMIP 未启用或在虚拟机中关闭 UMIP
cat > /tmp/sidt.c <<'EOF'
#include <stdio.h>
#include <stdint.h>
struct __attribute__((packed)) { uint16_t limit; uint64_t base; } idtr;
int main(void) { asm volatile("sidt %0" : "=m"(idtr)); printf("IDT base=%#lx limit=%#x\n", idtr.base, idtr.limit); }
EOF
gcc -o /tmp/sidt /tmp/sidt.c && /tmp/sidt
```

在启用 UMIP（User-Mode Instruction Prevention）的 CPU 上，内核会模拟 `sidt` 并返回一个伪造的值。在未启用 UMIP 时，可看到地址位于 cpu_entry_area 的固定位置（`CPU_ENTRY_AREA_RO_IDT`），且每次启动都相同，不受 KASLR 影响；`limit` 为 `0xfff`（256 × 16 − 1）。

## 小结

- x86 用 0～255 的向量号统一标识中断与异常；Linux 把 0～31 给 CPU 异常，`0x20`～`0xea` 给设备中断，`0xeb`～`0xff` 给本地定时器、IPI 等系统向量。
- IDT 的每一项是 16 字节的门描述符；Linux 全部使用中断门，保证入口代码在关中断状态下开始执行；只有 `int3`、`into`、`int $0x80` 的 DPL 为 3。
- TSS 在 x86_64 上只提供 `sp0` 与 7 个 IST 槽位；`sp0` 固定指向 cpu_entry_area 中的入口栈，以配合 PTI。
- #DF、NMI、#DB、#MC、#VC 使用 IST 栈以应对"当前栈不可信"的情形，代价是 IST 不可重入；设备中断则在 C 入口中由软件切换到 16 KB 的 per-CPU 硬中断栈。
- IDT 分五步建立：早期处理函数 → 早期 #DB/#BP → 真正的 #PF → 全部异常门 → 系统向量与设备中断桩；最后映射到 cpu_entry_area 的只读地址。
- 所有设备向量共享一组 8 字节入口桩，桩把向量号压在错误码槽位后跳到 `asm_common_interrupt`；FRED 在 v6.9 引入，本书配置下默认关闭。

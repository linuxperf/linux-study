# BPF 程序类型与挂载点：从触发场景读两套枚举

本文依据仓库中的 Linux 6.18.52 源码，覆盖 `enum bpf_prog_type` 中的 **32 个具体程序类型**和 `enum bpf_attach_type` 中的 **58 个挂载类型**。前者回答“程序处理哪类上下文”，后者在适用时进一步回答“同一类程序用于哪个 hook”。`BPF_PROG_TYPE_UNSPEC` 和两个枚举末尾的 `__MAX_*` 是边界值，不是可挂载的程序或 hook。[程序类型枚举](../../linux/include/uapi/linux/bpf.h#L1040-L1075) · [挂载类型枚举](../../linux/include/uapi/linux/bpf.h#L1077-L1136) · [类型与上下文注册](../../linux/include/linux/bpf_types.h#L4-L85)

先看一个会影响实际操作的区别：`BPF_PROG_TYPE_CGROUP_SOCK_ADDR` 是程序类型；`BPF_CGROUP_INET4_BIND`、`BPF_CGROUP_INET4_CONNECT` 等是它可以选择的挂载类型。加载时的 `expected_attach_type` 让内核按预期 hook 验证程序；挂载请求的 `attach_type` 指明此次实际使用的 hook。再用目标 fd 或设备索引选定具体对象。**仅加载程序不会把它挂到目标上。**[加载时检查并保存预期类型](../../linux/kernel/bpf/syscall.c#L2712-L2734) · [直接挂载取得程序及检查类型](../../linux/kernel/bpf/syscall.c#L4529-L4539) · [link 创建检查类型](../../linux/kernel/bpf/syscall.c#L5705-L5712)

## 1. 按事件发生的位置认识全部程序类型

表中的“入口”只指出本源码中可追踪的典型路径；同一个程序类型可能还有其他挂载方式。`BPF_PROG_ATTACH`、`BPF_LINK_CREATE`、socket 选项、perf event 与 netlink 是不同接口，不能从程序类型的名字推断具体要调用哪一个。枚举值存在也不保证当前内核配置启用了对应实现。[直接挂载命令分发](../../linux/kernel/bpf/syscall.c#L4538-L4563) · [link 创建分发](../../linux/kernel/bpf/syscall.c#L5714-L5790) · [受配置控制的程序类型注册](../../linux/include/linux/bpf_types.h#L4-L85)

# Linux 文档源码核对与修复

目标是让文档中的实现结论与本项目源码一致，并留下读者可以回查的证据。默认直接修复已确认的问题；用户明确要求只检查、只报告或不修改时，执行只读核对。

## 角色与逐文档分工

主 agent 负责确定范围、调度和最终复核。已经收到“文档核对子 agent”任务及唯一目标文件的 agent，直接执行下文的“单文档核对与修复”，不得再为该文档递归创建子 agent。

**每份目标文档必须单独新建一个对应的子 agent，只有一份文档时也必须创建。** 不得把多份文档交给同一个子 agent，不得复用已经检查另一份文档的 agent，不得以主 agent 自查代替这一要求。

### 主 agent 的调度

1. 定位包含 `linux/` 的项目根目录。用户指定文件时使用该文件；指定目录时递归列出其中的 Markdown 文档；未指定范围时默认检查 `book/` 下的 Markdown 文档，并向用户说明范围。不得将范围擅自扩大到其他目录。规范化实际文件路径并去重，避免路径别名导致同一文件被重复分配。
2. 阅读当前工作区状态，记录已有文档修改和本轮目标清单。为每个目标记录对应 agent、检查状态和结果；清单可以保存在工作上下文中，不默认新增报告文件。
3. 为每份文档新建子 agent，并发送下面列出的完整任务信息。并发数遵守当前环境的限制；有空闲名额才启动下一份文档，直至清单处理完毕。文档数量超过并发上限时分批排队，不能通过合并任务减少对应 agent 数量。
4. 每个子 agent 只能修改分配给它的文档；可以只读查看相邻章节及相关源码。主 agent 不与子 agent 同时修改同一文件，子 agent 也不能顺带修改目录索引或其他章节。跨文档问题分别交给这些文档各自的 agent 处理；范围外问题只报告。
5. 等待全部子 agent 返回，检查实际 diff、源码依据和结果覆盖情况。发现遗漏或修复错误时，把反馈发给该文档原有的 agent，完成修复后的复核；不要仅凭“已完成”的回复判定通过。

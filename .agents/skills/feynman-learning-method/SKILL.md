# 费曼学习法

帮助用户把一个概念讲清楚，并用新情境检验解释是否成立。学习闭环是“选定概念 → 自己解释 → 找出缺口 → 查证补学 → 简化重讲 → 验证应用”。表达流畅只能说明表达能力，不能单独证明理解正确。

## 确定本轮目标与形式

- 从用户给出的主题、材料和已有解释开始。主题过大时，先选一个能独立解释的小问题，并说明本轮边界；只有无法确定学习对象时才询问主题。
- 把目标写成可观察的能力，例如“能解释它解决什么问题、关键步骤为何成立，并预测条件改变后的结果”。结合用户背景选择必要的前置知识，不先发一长串背景调查。
- 用户要“带我学”“检查我的理解”时，采用互动练习。用户要“一次讲清楚”“生成学习笔记”或明确要求直接解释时，直接交付讲解，可以附自测题，不强迫用户先回答。
- 已有用户解释就直接检查，不重复要求从头讲。用户明确表示完全陌生时，先给一个短小的入门解释，再邀请其复述。
- 默认在当前对话中开展。仅在用户要求保存或修改文件时写入文件，不因学习任务自行改写书稿、创建长期计划或安排提醒。

## 互动学习闭环

### 1. 让用户先解释

邀请用户把概念讲给一个具备必要基础、但不了解该主题的人听。允许不完整的回答和“这里我不知道”。可提示其从用途、过程和一个例子入手，不在用户尝试前给出完整标准答案。

每轮围绕当前最重要的一个问题展开，等待用户作答后再推进。避免把大量术语、完整讲解和一组测验同时交给用户。

### 2. 用具体表述定位缺口

检查用户解释中的因果关系，而不只检查关键词是否出现：

| 检查方向 | 需要观察的证据 |
| --- | --- |
| 含义与用途 | 能说清是什么、解决什么问题，术语没有循环定义 |
| 机制与因果 | 能解释关键步骤为什么产生相应结果，而不只是列步骤或函数名 |
| 条件与边界 | 知道成立条件、容易混淆的对象，以及何时解释不再适用 |
| 举例与应用 | 能用具体例子说明，并在条件变化时给出有理由的预测 |

反馈锚定用户的具体句子：先指出有依据的正确部分，再聚焦会改变结论的缺口。区分事实错误、尚未解释的环节、表达歧义和资料不足；遗漏某项不等于用户不懂，可用一个问题确认。没有可靠证据时，标明待查证，不把记忆中的答案作为纠错依据。

### 3. 针对缺口补学

选择最妨碍当前理解的缺口，采用与其匹配的帮助：

- 因果跳步：询问中间发生了什么，或给出最小状态变化示例。
- 概念混淆：比较两个对象的职责、输入输出或成立条件。
- 边界遗漏：给出一个改变关键条件的反例，检查原解释是否仍成立。
- 事实不确定：回到允许使用的材料，定位能支持或推翻结论的证据。

根据用户反应从提示推进到短解释；用户明确要求答案时直接解释，不继续反复追问。补学只覆盖当前缺口和必要前置知识，不扩展成整个学科的教程。

### 4. 简化并重新讲述

邀请用户用自己的话重新解释刚修正的部分，再将其接回整体机制。需要时示范如何把一句模糊表述改成可验证的因果句。

简化时先讲用途和整体过程，再引入必要对象与细节。保留会影响结论的条件、单位、状态变化和例外；通俗表达不意味着删除关键约束。类比要说明对应关系和失效边界，不能用类比替代真实机制。伪代码或概念图明确标注简化范围。

### 5. 检验复述与迁移

在用户重讲之后，选择一个与原例子不同、但仍在本轮范围内的情境，要求预测结果并说明理由。例如改变一个条件、比较相似机制，或追踪一个对象的状态变化。

互动练习中，检验题与答案分开给出，让用户先尝试。若回答暴露新的关键缺口，回到针对性补学；若能独立解释机制、说明关键条件并处理新例子，可说明本轮目标已有回答证据支持。不要以“听懂了”、照抄示范答案或语言流畅判定掌握，也不要据此推断长期记忆。

用户要求结束或转为直接讲解时，按其要求收束，不为完成固定轮数继续测验。尚未收到复述或应用回答时，标明“尚未验证”，不得替用户编造回答或声称学习完成。

## 直接讲解与学习笔记

先解释问题与用途，再展示整体机制，随后解释支撑机制的核心对象和关键因果关系。用一个具体例子贯穿讲解，说明适用条件和常见误解。复杂主题按本轮边界展开，避免逐项翻译材料。

需要自测时，题目应检查解释、预测或辨析能力。用户要含答案的笔记时，将参考答案放在题目之后单独标注。交付的解释和答案属于辅助材料，不能作为用户已经掌握的证据。

## 本仓库的 Linux 内核学习

分析内核时遵循[项目写作规范](../../../AGENTS.md)，并让通俗解释保留可回查的实现依据：

- 只以本项目 `linux/` 源码为实现依据，可参考其中的 `Documentation/`；已有书稿用于衔接和定位，不能代替源码。不得联网或用其他版本补全结论。
- 从本地 `linux/Makefile` 确认版本；架构相关分析只选 x86。关键分支核对 `linux/.config` 及相关构建条件，区分内建、模块和运行时条件。配置缺失或不足时说明限制，不生成或修改配置。
- 默认读者具备 C 语言与操作系统基础。先解释机制解决的问题与概览流程，再围绕核心数据结构的关系、状态和生命周期解释算法，不把调用栈当作讲解主线。
- 纠正具体实现结论前，用 `rg` 定位并读取定义及相关使用路径；按问题核实调用、初始化、释放、同步或失败处理。需要引用行号时用 `nl -ba` 实际确认，不能沿用未核实的旧引用。
- 区分源码事实、概念模型和作者推断。简化不省略会改变结论的锁、引用、重试、错误处理和配置条件；不知道的部分明确标注待查证。
- 写入 Markdown 时，源码链接按目标文档的位置计算相对路径，并使用已确认的行号锚点。学习与验证不修改 `linux/`，也不默认编译内核或安装依赖。

## 回合反馈与收束

让用户看到本轮已经确认的理解、最需要补足的环节，以及下一步的一个具体任务。根据已有回答调整反馈，不机械套用所有检查项，不给没有量表依据的掌握分数。

结束时简要留下可复用的核心解释、已修正的误解、仍待查证或未验证的点；涉及实现结论时附上对应证据。总结依据实际发生的学习过程，避免泛泛表扬或宣称已经全面掌握。
